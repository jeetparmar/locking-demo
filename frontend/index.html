      Retrying (optimistic): on a 409 the client reloads the seat and tries again, usually 2 to 3 times. Here the retry would find the seat booked, so it stops. Short transactions (pessimistic): every waiter holds a database connection while it blocks, so long transactions exhaust the pool.

      Transactions and isolation Simulation

      @Transactional wraps a method in one transaction. It commits when the method returns. It rolls back on unchecked exceptions by default; checked exceptions need rollbackFor. Pick a level to see what it allows:
